> 1. **BẮT BUỘC PHẢI HỎI DASTAN:** Nhắn tin trực tiếp hỏi Dastan xem anh ấy **đã tạo draft ticket hoặc kịch bản kiểm thử (draft test cases) cho ticket đó chưa**.

#### 📌 Chi Tiết Các Bước Triển Khai (Step-by-Step Flow Chuẩn)

1. **Bước 0: Pre-check với Dastan (Bắt buộc - Chống Duplicate):**
   - Xác định ticket Jira cần kiểm thử.
   - Nhắn tin hỏi Dastan trên Slack xem đã tạo draft ticket / test cases chưa. Nếu Dastan đã tạo, tiếp nhận và hoàn thiện tiếp, tuyệt đối không tự tạo bản mới song song tránh bị duplicate.

2. **Bước 1: Khởi tạo Draft qua Claude (`/create-draft-test-execution`):**
   - Thu thập tài liệu đặc tả: Jira Ticket, Confluence Spec, PR diff.
   - Chạy lệnh `/create-draft-test-execution` để AI sinh ra file markdown kịch bản nháp. Cập nhật Jira sang **`In Progress`**.

3. **Bước 2: Rà soát & Hoàn thiện kịch bản trên VS Code:**
   - Mở file markdown kịch bản trên VS Code để rà soát chi tiết.
   - Kiểm tra kỹ các điều kiện: Precondition, Test Steps, Expected Results, Phân quyền Roles/Grants, Edge Cases.

4. **Bước 3: Chuẩn hóa Description, Bảng Kịch Bản, Liên Kết Ticket & Đổi Trạng Thái Jira (`Designing`):**
   - Đưa bảng kịch bản Markdown vào Jira Description / Test Section.
   - **Lưu ý bắt buộc về Endpoint:** Phải chỉ định rõ ràng tên **Endpoint API** (`URL`, `Method`, `Payload`) hoặc Module chức năng liên quan.
   - **Quy tắc Linked Work Items (Bắt buộc):** Tại mục Linked Work Items / Linked Issues, chọn mối quan hệ/trạng thái là **`tests`** và liên kết trực tiếp tới **Request Ticket** tương ứng (ví dụ: `QA-xxxx` tests `GTO-xxxx`).
   - **Liên kết Epic cha:** Chỉnh sửa ticket và liên kết vào Epic cha tương ứng: **`QA-3614: Transfer Tools Enhancement and feedback`**.
   - **Chuyển trạng thái ticket Jira:** Cập nhật trạng thái ticket Jira sang **`Designing`**.

5. **Bước 4: Tạo Test Artifact sang Confluence (`/create-test-artifact`) & Đổi Trạng Thái Jira (`Testing` 🚀):**
   - **Thực hiện ngay sau khi tạo/cập nhật xong ticket Jira:** Chạy lệnh `/create-test-artifact` để đồng bộ toàn bộ tài liệu đặc tả kiểm thử sang không gian Confluence của dự án.
   - **Chuyển trạng thái ticket Jira:** Cập nhật trạng thái ticket Jira sang **`Testing`** 🚀 để chuẩn bị thực thi kiểm thử.

6. **Bước 5: Thực thi Kiểm thử trên Staging & Nghiệm thu (Sign-off) Hoàn tất Ticket Jira (`Pass Test` ✅):**
   - Khi ticket đã ở trạng thái **`Testing`** 🚀 và Dev hoàn tất build và deploy lên Staging:
   - Tiến hành thực thi kiểm thử trực tiếp trên môi trường Staging theo bộ kịch bản đã chuẩn bị (bao gồm test chức năng, UI, API và Regression).
   - **Nghiệm thu (Sign-off) & Hoàn tất Ticket Jira:** Khi kiểm thử thực tế đạt kết quả 100% Passed ➔ Chuyển trạng thái ticket Jira sang **`Pass Test`** ✅ để hoàn tất nghiệm thu ticket và tag các reviewer (**Dastan**, **Mohit**, **Sandeep**).

7. **Bước 6: Gửi Dev Review & Thông báo UAT Testing (@tiffany.kao, @jento.chan) qua Slack:**
   - **Nghiệm thu (Sign-off) & Hoàn tất Ticket Jira (`Pass Test` ✅) trên môi trường QA xong mới làm bước 6:**
   - **Gửi Dev Review:** Nhắn tin qua Slack cho Dev phụ trách thông báo ticket đã Pass Test và gửi kèm link Jira/Confluence để Dev review:
     > 💬 *"Hi @dev, ticket `<TICKET_KEY>` has been tested and passed (Pass Test ✅). Here is the detailed test section: `<Jira_Link>`. Could you please help review? Thank you!"*
   - **Thông báo UAT Testing cho Ops:** Khi đã hoàn tất testing QA và tính năng đã được setup trên UAT, gửi tin nhắn Slack cho Ops (**@tiffany.kao** và **@jento.chan**) để nhờ test trên UAT theo mẫu:
     > 💬 *"hi @tiffany.kao , @jento.chan we have completed testing for `<TICKET_KEY_AND_TITLE>` on QA environment. And we already set it up on UAT environment, please help testing it on UAT. Thank you! 🙏*  
     > *UAT UI deployed at: `web-reports.uat-gp.galaxydigital.io/fund_transfer_tool`"*  
     *(Đính kèm preview card Jira Cloud của ticket, ví dụ: Task `GTO-16167`)*
   - Chờ Dev xác nhận review OK và Ops test UAT.

8. **Bước 7: Tạo Test Case & Test Run trên TestRail (`/Create-testrail-cases-from-confluence` & `/Create-TR-Run-From-TR-Draft`):**
   - **Sau khi Dev đã review OK xong xuôi, lúc này mới bắt đầu làm bước 7 (TestRail):**
   - Cấu hình TestRail: Project ID `30`, phân loại đúng suite: API `945`, UI `946`, E2E `947`.
   - **Thao tác 2 công đoạn bắt buộc:**
     1. Chạy lệnh **`/Create-testrail-cases-from-confluence`** để AI đọc tài liệu Confluence spec & Jira Ticket và sinh ra file markdown (`.md`) kịch bản test cases nháp chuẩn format TestRail.
     2. Sau khi đã có file markdown draft từ bước trên, chạy tiếp lệnh **`/Create-TR-Run-From-TR-Draft`** để tự động import test cases vào TestRail theo đúng Suite ID (`945`/`946`/`947`), tạo Test Run chính thức và đính kèm evidence kiểm thử (All Passed ✅).

#### 📌 Chi tiết từng bước thực hiện:
1. **Bước 1: Create Test Scenario Prompt:** Đọc kỹ API spec / requirement, viết prompt chi tiết để AI phân tích và sinh bộ kịch bản test đầy đủ 4 tầng.
2. **Bước 2: Create New Branch & Sync Code:** Đồng bộ mã nguồn từ `main` về nhánh endpoint theo flow chuẩn: `git switch main` ➔ `git pull` ➔ `git fetch origin` ➔ `git switch main` ➔ `git pull origin main` ➔ `git switch <endpoint>` ➔ `git pull` ➔ `git pull origin main` (lấy code về sửa lại theo điều kiện). Tạo branch độc lập `<branch-name>-<endpoint>`, chuyển Jira sang `In Project`. Tuân thủ: 1 Branch - 1 Endpoint.
3. **Bước 3: Complete Scenario:** Mở file markdown do AI sinh, hoàn thiện preconditions, test steps, payload và expected assertions.
4. **Bước 4: Review Code:** Tự review code test script, fixtures, auth headers. Bắt buộc gọi `load_dotenv()` ở đầu file nếu test truy vấn DB.
5. **Bước 5: Run Code:** Thực thi chạy bộ test suite automation trên môi trường cục bộ đảm bảo Pass 100%.
6. **Bước 6: Fix Code:** Sửa các lỗi assertion fail, type mismatch hoặc format response cho đến khi toàn bộ test cases đều Pass.
7. **Bước 7: Create TestRail:** Dùng lệnh `/create-testrail` để tạo mới test cases trên TestRail và `/sync-testrail` để đồng bộ ID test cases trực tiếp lên Jira ticket.
8. **Bước 8: Run Review Code:** Chạy lại toàn bộ test suite cục bộ để đảm bảo việc liên kết TestRail không gây ra lỗi hồi quy (regression) và vẫn Pass 100%.
9. **Bước 9: Check Orphan Functions (`/review-code`):** Chạy `/review-code` để AI quét và xóa các hàm mồ côi (không còn được gọi trong suite).
10. **Bước 10: Kiểm tra model Pydantic:** Rà soát các model Pydantic khớp 100% với JSON response thực tế, không thiếu trường, tránh lỗi ValidationError trên CI/CD.
11. **Bước 11: Commit and Push Code:** Commit với message chuẩn convention và push code lên remote branch.
12. **Bước 12: Create PR Summary:** Chạy lệnh `/pr summary` để AI tự động tạo phần tóm tắt cho Pull Request.
13. **Bước 13: Create Pull Request:** Mở PR trên GitHub vào nhánh `main`, dán nội dung PR summary, đính kèm ảnh chụp màn hình test Pass 100% và gán reviewer (**Dastan**).
14. **Bước 14: Update Review Status:** Gán link PR vào Jira ticket và chuyển trạng thái ticket sang **`Under Review`**.
15. **Bước 15: Request Review & Merge ➔ `Done` ✅:** Nhắn Dastan trên Slack nhờ review PR, xử lý góp ý qua `/resolve-pr`, merge vào `main` và chuyển Jira sang **`Done`** ✅.

## 💡 Ghi nhớ / Ideas
- 🔑 **"Hỏi Dastan trước, tạo Draft sau":** Bất cứ khi nào nhận ticket mới, kiểm tra trước với Dastan để chống trùng lặp dữ liệu (Zero Duplication).
- 🔑 **"Jira xong là Artifact liền tay":** Tạo hoặc cập nhật ticket Jira là phải chạy ngay `/create-test-artifact` để tài liệu Confluence luôn ở trạng thái mới nhất.
- 🔑 **"Nghiệm thu (Sign-off) & Hoàn tất Ticket xong mới làm Bước 6 Bước 7":** Hoàn tất nghiệm thu (chuyển Jira sang `Pass Test` ✅) xong xuôi ➔ mới làm Bước 6 (Gửi Dev Review qua Slack) ➔ rồi mới làm Bước 7 (Tạo Test Case & Test Run trên TestRail).
- 🔑 **"1 Branch - 1 Endpoint":** Mỗi nhánh chỉ làm cho 1 endpoint duy nhất, test chạy pass 100% cục bộ rồi mới sync TestRail và mở PR.
